Abstract
Accurate multivariate time-series classification requires extracting temporal features and integrating information across a sequence. Weight-tied refinement offers a way to repeatedly process these features without allocating new parameters at each stage. Applying this principle to time series requires choosing both a temporal representation and a latent-state organization suited to classification. We introduce the Recursive Time-Series Model (RTSM), which combines a learned convolutional temporal tokenizer, single-state weight-tied refinement, and a pooled classification readout. Across all 30 UEA datasets, RTSM achieves 72.81% mean accuracy under validation-based configuration and checkpoint selection, the highest observed mean among the 17 evaluated deep-learning models and 1.60 percentage points above MambaSL. Ablations on eight datasets favor the proposed tokenizer over a simple convolutional embedding and the single-state model over the tested two-state variants. The complete classifier reaches 86.10% mean accuracy versus 84.79% for a separately trained tokenizer-only classifier. These findings identify temporal encoding and state organization as key design choices for adapting recursive architectures to time series. The resulting classifier combines competitive accuracy with a shared refinement module whose parameter count is independent of computational depth.

Multivariate

The UEA archive illustrates the diversity of this task, with datasets that differ substantially in sequence length, dimensionality, and training-set size

Weight sharing allows repeated computation without allocating a separate set of weights to each processing stage. Recent

Background and related work
2.1
Multivariate Time-Series Classification
Time-series classifiers differ in how they extract temporal features and combine them into a sequence-level prediction. ROCKET and MultiRocket use fixed convolutional filters, pooled feature summaries and linear classifiers
(

;

. Neural approaches learn representations jointly with the prediction objective: ModernTCN uses a convolutional backbone
(

We therefore study the adaptation as a complete classification architecture, assessing temporal tokenization and state structure alongside refinement depth.

RTSM
adapts recursive computation to multivariate classification through temporal encoding, a single latent state, and a sequence-level readout. A convolutional tokenizer first converts the observations into temporal feature vectors, or tokens. A shared attention-based module then updates a latent state containing one vector per token. Weight reuse and deployment.
At its reference inference budget,
RTSM
applies the same 6.82-million-parameter refinement module 48 times. Allocating independent weights to each application would require 327.16 million refinement parameters—a 48-fold difference in refinement-weight storage. At 16 bits per weight, these footprints correspond to 13 MiB and 624 MiB, respectively, excluding the tokenizer, readout, and activations. Reusing the smaller weight set creates an opportunity to reduce off-chip memory traffic when weights remain resident on-chip. This mechanism has demonstrated substantial gains in other recurrent architectures:
Diamos et al. (2016)
report approximately
30
×
30\times
higher recurrent-kernel throughput than a matrix-multiplication implementation on a Titan X
Graphics Processing Unit (GPU)
, using
1,152
1{,}152
hidden units and a batch size of four. These results motivate hardware-aware implementations of
RTSM
for edge devices and
GPU
inference, with benefits depending on memory capacity, activation traffic, and execution scheduling.
5
Conclusion
We introduced
RTSM
, an adaptation of recursive architectures to multivariate
TSC
through a learned temporal tokenizer, single-state weight-tied refinement, and a pooled sequence-level readout. Across the 30 UEA datasets,
RTSM
achieves
72.81
%
72.81\%
average accuracy under validation-based selection, the highest observed mean among the evaluated deep-learning models. Eight-dataset ablations favor the proposed temporal tokenizer over a simple convolutional embedding and the single-state formulation over the tested two-state variants. The complete architecture also improves on a separately trained tokenizer-only classifier by
1.31
1.31
percentage points on this subset.
Depth and state-reset ablations identify several refinement schedules with similar mean accuracy.
RTSM
combines strong classification accuracy with a learned temporal encoder, one latent state, and a refinement module whose parameters are reused across computational depth.

A.1
Protocol and Implementation Specifications
Implementation and Computational Environment
The published MambaSL benchmark results reused in this work were obtained using Python 3.12.8 and PyTorch 2.5.1, primarily on NVIDIA GTX 1080 Ti GPUs, with A100 GPUs used for memory-intensive runs. Classical baselines were evaluated with
aeon

(
Middlehurst et al., 2024
)

(
Jung & Kim, 2026

RTSM

3.4

(
Fusco et al., 2024
)
, including
RTSM
under both protocols and the validation-protocol re-evaluation of the deep-learning baselines using the corresponding MambaSL implementations adapted to the validation-based training and selection procedure.

Adaptive halting allows different samples to complete their training trajectories after different numbers of supervision steps. The slot-buffer scheduler maintains a completion counter

MambaSL Protocol
The
MambaSL protocol
follows the evaluation procedure of MambaSL
(
Jung & Kim, 2026
)
. Models are trained on the complete official UEA training partition, while the official test partition is evaluated during training and used for model and checkpoint selection as well as early stopping. We reuse the published results for MambaSL and its 20 baselines and evaluate
RTSM
under the same selection procedure.
Validation Protocol
The
validation protocol
removes test-set involvement in model selection by partitioning the official UEA training set into an 80/20 stratified train-validation split. The official test partition is reserved for final evaluation, while model configurations and checkpoints are selected by highest validation accuracy, using validation loss as a tie-breaker between configurations. No early stopping is used under this protocol. We re-evaluate the deep-learning baselines and
RTSM
under this protocol while retaining their respective model search spaces. The validation-protocol comparison contains only the deep-learning models; the five non-deep-learning baselines are included in the separate MambaSL-protocol comparison.
Normalization.
The reported
RTSM
benchmark includes two historical normalization implementations: statistics were fitted either on the full official training partition before the 80/20 split or on the 80% training subset after splitting. Both apply the fitted statistics to held-out data; neither fits the
RTSM
normalizer on the official test set. The shared UEA loader used for the re-evaluated baselines standardizes each partition independently, so validation and test statistics are not used to normalize training inputs. Model-specific transforms follow the respective baseline implementations. The comparison therefore reflects the complete model, training, and preprocessing pipelines.

Recursive Architecture and Training Ablations
Configuration names encode the corresponding architectural and training
choices.
H
denotes the number of outer recursive cycles,
L
the number of inner cycles used by two-state variants,
and
G
the number of H-cycles through which gradients are propagated;
accordingly,
2G
/
3G
extend the gradient window.
stepsN
denotes the maximum number of deep-supervision steps.
For two-state models,
shared
uses a single reasoning network
f
f
for
both state updates, as in
TRM
(
Jolicoeur-Martineau, 2025
)
, whereas
separate
uses distinct
f
H
/
f
L
f_{H}/f_{L}
networks, implementing the network
separation used by
HRM
(
Wang et al., 2025a
)
. All other training choices follow
the
TRM
recipe, including its gradient schedule, loss, halting, and parameter
EMA; hence, the separate-network variant is not an evaluation of
HRM
itself.
Conv
denotes the simple convolutional patch tokenizer, which uses
strided 1-D convolutions to map local temporal windows into patch
representations; configurations
without this prefix use the proposed time-series tokenizer.
Additional suffixes denote further architectural or training modifications.
tokenizer_only
omits the attention-based refinement stage and applies the
sequence-level prediction head directly to the tokenizer representation.
nocarry
resets the latent state between supervision steps.
forcefull
disables
Q-based halting and forces every sample through the full training-step budget.
mlpt
replaces attention with a temporal
MLP
.
meanpooling
and
adaptivepooling_noQ
replace the default pooling
operation. The latter applies learned weighted pooling only to the classification head, whereas the reference model applies learned weighted pooling to both the classification and halting heads.
rima
enables the learned EMA-style latent-state reweighting
